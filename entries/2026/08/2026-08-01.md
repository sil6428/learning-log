## What I learned

- T3MP3ST is an orchestration and security-testing framework, not an Ollama model. Ollama supplies the reasoning model behind the framework.
- A browser action travels through the local Express API, the T3MP3ST LLM adapter, and Ollama's `/api/chat` endpoint before the answer or proposed tool call returns to the interface.
- Parameter count does not equal runtime memory directly. Quantization reduces model weight size, while context length, inference buffers, and application overhead add memory beyond the downloaded file.
- On this 16 GB system, a 3B model is workable but still leaves little headroom when other applications already consume most of the RAM. A 7B or 8B model would be much more likely to page to disk.
- Binding the War Room to `127.0.0.1` matters because its API can execute approved tools. It should not be exposed to a LAN or the public internet without authentication and a properly configured reverse proxy.
- Authorized scope and rules of engagement must be defined before any active testing.
- A desktop metaphor needs navigation, window state, task switching, search, status feedback, and predictable controls in addition to file icons.
- Native buttons and links provide keyboard behavior without rebuilding it in JavaScript.
- A simulated file system works best when its folder structure reflects real portfolio categories instead of generic sample data.
- Full-screen mobile windows preserve the desktop metaphor while avoiding tiny floating panels on narrow screens.
- Separating the operating-system layer from the Three.js scene keeps the room responsive while allowing the file interface to remain readable and accessible.
- Desktop icon placement becomes clearer when spatial groups and file-type order communicate where content belongs before the visitor opens a folder.
- One keyboard shortcut can serve different interface layers when the active context is detected before choosing which terminal to open.
- Embedding the existing PDF preserves the original resume layout while still providing accessible full-size and download fallbacks.
- A simulated shell feels connected to the portfolio when its commands navigate real folders and reuse the room's existing event system.
- Hidden legacy hit areas can survive a visual redesign. Interaction-state tests need to confirm which raycast targets are enabled after every transition, not only what is drawn on the monitor.
- Touch and mouse navigation should be configured independently. OrbitControls supports a mobile-first gesture map without changing the established desktop button map.
- A convincing shutdown must reset visual, interaction, animation, and hardware-indicator state together. Hiding the operating-system overlay alone leaves the scene in an inconsistent powered state.
- A skills section is more credible when every skill is tied to a specific project, lab, deployment, or work responsibility.
- Private development records should be described without exposing their repository URL in a public portfolio.
- Invisible Three.js hotspots still affect surrounding systems when shared marker logic reads their positions. Retired targets should be removed instead of only hidden.
- One marker for the full computer communicates the current interaction more clearly than several overlapping markers from an obsolete interface.

## Problem encountered

- PowerShell's script-execution policy blocked the `npm.ps1` shim, so the Windows executable shim `npm.cmd` was used instead.
- T3MP3ST's doctor script reported several installed Windows commands as missing because its command detection expects Unix-style tooling.
- The CLI connection-test path incorrectly required an API key for the keyless local provider, so the underlying T3MP3ST adapter was tested directly.
- `npm audit` reported two high-severity transitive dependency findings: vulnerable `brace-expansion` versions reached through ESLint tooling and a vulnerable `postcss` version reached through Vitest and Vite. No forced dependency rewrite was applied.
