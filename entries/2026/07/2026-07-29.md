## What I learned

- A visual system feels more personal when it reflects the subject of the portfolio instead of following a common layout.
- Interactive visuals are more useful when they also support navigation instead of acting only as decoration.
- A spatial desktop layout still needs a simpler mobile information hierarchy.
- Raycasting connects pointer coordinates to objects inside a 3D scene and makes a model function as navigation.
- Orbit controls need limits so visitors can inspect a scene without losing the intended composition.
- An interactive 3D interface still needs a standard accessible path to every destination.
- Three.js scenes need careful cleanup of animation frames, geometry, materials, event listeners, and renderer resources.
- Pointer, scroll, mobile, and reduced-motion behavior should be designed together instead of added separately.
- Browser-selected audio files can play locally through object URLs without uploading or storing the file.
- Keeping a restore branch before a large redesign makes experimentation safer.
- A social preview should use the same visual language as the live site.
- Camera interpolation makes navigation feel spatial while a delayed HTML panel keeps longer text readable.
- 3D interactions work best as progressive enhancement. Visible buttons and normal routes keep the content usable without precise pointer input or WebGL controls.
- Scene state, camera state, and interface state need one transition sequence so panels do not appear before the visitor understands which object was selected.
- Object-relative camera offsets are more reliable than unrelated world coordinates because the framing remains tied to the model even when the room rotates.
- Small repeated geometry, such as keyboard keys, ports, vents, pages, and strings, makes simple primitives read as recognizable objects without importing large models.
- Keeping the long text in HTML panels preserves readability and accessibility while the Three.js scene supplies spatial context.
- A memorable 3D portfolio needs a repeatable interaction loop. Movement, approach, feedback, inspection, and return give visitors a reason to understand the space.
- A damped chase camera needs separate smoothing for camera position and look target so motion feels responsive without becoming shaky.
- Proximity prompts reduce guesswork because visitors know when a 3D object is close enough to inspect.
- Device-local progress adds a sense of discovery without collecting visitor data or requiring authentication.
- Open-source references are most useful when studying architecture and interaction patterns, then applying them through an original concept with clear license attribution.

## Problem encountered

- Adding Three.js increased the client bundle size, so the scene was kept focused and limited to one shared visualization.
- Changing the homepage wording and preview image required updating existing rendered-output tests.
- Fixed-position controls competed for the same mobile space, so the soundtrack now moves when the footer cat house is visible.
- A full-screen scene leaves less room for navigation and content, so the directory and object panels required separate tablet and mobile layouts.
