## What belongs here

- Networking and Cisco lab notes
- Cybersecurity exercises and write-ups
- Python security tooling, reproducible research, and web development practice
- Testing, deployment, and technical documentation work
- Nonprofit technology operations that are safe to record
- Problems solved, decisions made, and next steps

## What does not belong here

- Empty commits
- Generated filler
- Backdated work
- Secrets, credentials, personal data, or private production information

## Weekday workflow

1. Do a real study, lab, or development session.
2. Run `scripts/new-entry.ps1` from PowerShell.
3. Fill in the generated note under `entries/YYYY/MM/`.
4. Remove every placeholder.
5. Commit once the entry describes completed work.

## Good commit messages

- `Document VLAN trunking lab`
- `Record Python password validation exercise`
- `Summarize authentication research`
- `Log nonprofit website hosting decisions`
- `Document portfolio publication and testing`

## Entry quality check

Before committing, make sure the note answers:

- What did I work on?
- What changed or what did I learn?
- What evidence did I produce?
- What problem did I hit?
- What is the next step?

Consistency matters more than commit count.
